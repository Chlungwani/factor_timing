# Chapter 3 review notes

Reviewed against the current repository on 25 October 2026. These notes support a separate revised chapter; the original thesis remains unchanged. This is a documentation review, not a pipeline correction or model rerun. Earlier Chapter 4 alignment notes contain historical configurations and should not override the current notebooks and saved data.

| Item | Verified implementation and required qualification |
|---|---|
| Validation configuration | All three current modelling notebooks, including their executed counterparts, set `CV_SPLITS=5`, `CV_TEST_SPLITS=2` and `PURGE_GAP=12`. There are 10 held-out-group combinations. Four complete CPCV paths are possible in theory, but the implementation scores the 10 folds and averages their AUCs; it does not assemble and evaluate four complete prediction paths. Do not describe independent path performance. |
| Sample and dates | `lagged_data.csv` contains 929 rows and 50 predictors. Joining valid trend labels and dropping unavailable terminal labels leaves 919 rows, dated 18 June 2007 to 20 January 2025, for each factor pair. The last 156 rows form the evaluation block, 31 January 2022 to 20 January 2025. These dates differ from older outputs that forward-filled terminal target labels. |
| Expanding evaluation | With `lookback=None`, training expands. The 12-row gap gives 751 fitting observations for the first evaluation prediction and 906 for the final prediction. Models refit each week; retuning occurs after 52 and 104 evaluation predictions, in addition to initial parameter selection. This is not a fixed-size rolling window. |
| Trend-scanning horizon | The implementation uses `span=(1,12)` and Python `range(*span)`: candidate window lengths are 1 through 11 observations, including the starting observation. The farthest return used is at `t+10`. A 12-row exclusion is therefore conservative relative to this implementation. Maximising an absolute t-statistic is a selection rule, not a statistical-significance test; no positive significance threshold is applied. |
| Initial tuning boundary | Initial parameter selection uses all 763 rows preceding the 156-row evaluation block, without the 12-row outer boundary exclusion used in walk-forward fitting. Some final pre-evaluation labels depend on returns inside the early evaluation block. Do not claim that the entire model-selection procedure is strictly separated from future evaluation information. This requires a code correction and rerun to resolve, rather than a wording change. |
| Scaling | Logistic and GAM walk-forward fits refit `StandardScaler` on the available, purged training window each week. During their hyperparameter tuning, scaling is fitted once on the whole tuning window before internal CV folds, rather than separately within each fold. The preprocessing notebook also writes a full-sample `scaled_data.csv`, but the current model notebooks load unscaled `lagged_data.csv`; do not claim that the unused global scaler is used for their final evaluation. |
| Feature clustering | MI is estimated once using the full available feature sample, not re-estimated inside each historical training window. This is unsupervised, but still uses future feature-distribution information. It does not establish a fully real-time feature-selection design. |
| Ward linkage input | `cluster_features` calls `linkage(D, method='ward')` with the full two-dimensional MI-distance matrix. SciPy treats its rows as observation vectors and applies Euclidean Ward clustering to their distance profiles. It does not treat the matrix as a precomputed condensed dissimilarity vector. Describe this as Ward clustering of MI-distance profiles. The threshold of 2 is a linkage height on those profiles, not a direct MI-distance cutoff. Representative selection subsequently minimises the mean original MI-distance within each cluster. A small local numerical check confirmed that this call equals `linkage(pdist(D), method='ward')` and differs from `linkage(squareform(D), method='ward')`. |
| Availability and missing values | The preprocessing notebook shifts features by four weekly rows. It uses both forward filling and backward filling, and the model data loader also calls `.ffill().bfill()`. A four-week lag does not by itself establish publication-date or revision-vintage availability. Avoid guarantees of real-time availability or complete elimination of leakage. |
| SHAP interpretation | Each explanation routine fits a separate model on the 763 pre-evaluation rows using the initially selected parameters, without the outer 12-row exclusion. Importance is mean absolute log-odds contribution over those training observations. Logistic uses coefficient-based additive contributions, GAM explains a logit wrapper, and XGBoost uses Tree SHAP. These explain descriptive pre-evaluation refits, not the 156 changing walk-forward models or their retuned parameter regimes. They do not establish causal importance, feature stability, or an explanation of realised evaluation performance. |

The revised chapter should distinguish intended safeguards from implemented safeguards. Statistical discrimination and proper probability scoring do not by themselves demonstrate calibrated probabilities, economic profitability or deployable factor timing. Those claims require their own evidence.
